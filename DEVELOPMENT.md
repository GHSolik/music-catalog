# Правила разработки Music Catalog

## Общие договорённости

- Используем существующий Django-проект и приложения `catalog` и `accounts`.
- База данных — SQLite.
- Интерфейс — Django Templates, HTML, CSS и при необходимости JavaScript.
- Все страницы наследуют `templates/base.html`.
- Общие стили размещаем в `static/css/`.
- Изменения моделей и миграций согласовываем с командой.
- Не коммитим `.venv/`, `db.sqlite3`, `media/`, `__pycache__/`.
- Работаем в отдельных Git-ветках, изменения в `main` объединяем через Pull Requests.

## Планируемые маршруты

| Имя URL | Адрес |
|---|---|
| `home` | `/` |
| `artist_list` | `/artists/` |
| `artist_detail` | `/artists/<int:pk>/` |
| `album_list` | `/albums/` |
| `album_detail` | `/albums/<int:pk>/` |
| `artist_create` | `/artists/add/` |
| `album_create` | `/albums/add/` |
| `track_create` | `/albums/<int:pk>/tracks/add/` |

Маршруты авторизации размещаем в приложении `accounts`.

**Важно:** таблица содержит согласованные имена для будущей реализации, а не уже работающие маршруты.

## Правила интеграции

- Перед началом новой задачи обновляем локальную ветку `main`.
- Не изменяем чужие файлы без необходимости.
- Перед Pull Request запускаем `python manage.py check`.
- Новые миграции включаем в коммит.
- Не удаляем чужие миграции для исправления конфликтов без обсуждения.
- В Pull Request кратко описываем сделанные изменения и способ проверки.
